# evidence-compose — 증거 이미지 글자 합성 도구

AI 이미지 생성은 날짜·시각·등록번호·한글을 자주 틀리게 그립니다. 그래서 역할을 나눕니다.
- **AI:** 배경, 인물, 종이 질감 같은 **글자 없는 바탕 그림**
- **이 도구:** 그 위에 **정확한 글자**를 합성

외부 패키지는 쓰지 않습니다. Node 22 이상과 Chrome 또는 Edge가 필요합니다. 브라우저는 게임 테스트와 같은 `tests/lib/browser.js`로 제어합니다.

## 값은 어디서 오나
| 값 | 출처 |
|---|---|
| 문자열, 시각, 금지 문구, 참조 자료, 제작 상태 | `docs/EVIDENCE_IMAGE_SPEC.md` §4-2 데이터 블록 |
| 등록번호, NVR 표시 오차 규칙, 면담 녹음 구간 | `docs/STORY_CANON.md` (B장, D장) |
| 글자 위치와 크기 | `layouts.js` (이야기 문자열은 없음) |

문구를 바꿀 때는 SPEC 데이터 블록 한 곳만 고칩니다. 등록번호는 CANON 한 곳만 고칩니다.

## 명령
저장소 루트에서 실행합니다.

```
node tools/evidence-compose/compose.js check [ID...]   # 데이터 검사(기본: 9장 전체). 브라우저 불필요
node tools/evidence-compose/compose.js refs [ID...]    # 기존 이미지(크기·해시)와 참조 자료 목록
node tools/evidence-compose/compose.js sample [ID...]  # 배치 시안(기본 3종: E10 보고서, E07 녹음, E03 NVR). 임시 바탕이므로 완성본 아님
node tools/evidence-compose/compose.js render <ID> --base <바탕 그림.png|webp> [--out <폴더>]
        [--draw-clock]   벽시계를 합성 (바탕 그림의 시계 바늘이 틀릴 때, NVR 템플릿)
        [--cctv-filter]  CCTV 색감·주사선 적용 (NVR 템플릿)
        [--sample]       'SAMPLE · 게임용 아님' 표시와 종이·휴대폰 틀을 함께 그림
        [--layout <키>]  같은 ID의 다른 바탕용 배치를 사용 (예: E15_v2). 없으면 ID 이름의 배치
```

- 결과는 기본으로 `tools/evidence-compose/output-preview/`에 저장됩니다.
  - `<기존 파일명>.webp`: 합성 결과
  - `index.html`: PC 폭과 모바일 폭(340px) 미리보기, 자동 검사 결과, 사람이 확인할 항목
  - `report.json`: 검사 결과
- 검사에 실패하면 종료 코드가 1입니다.

## 바탕 그림에 맞추는 선택 배치 옵션 (`layouts.js`)
모두 선택 사항이며, 없으면 기존과 똑같이 그립니다. `--sample`에서는 쓰지 않습니다.
- `phone.quad: [[x,y]×4]` — 휴대폰 화면 네 모서리(좌상·우상·우하·좌하). 비스듬히 놓인 휴대폰에 원근을 맞춥니다. 화면이 줄어드는 만큼 글자를 키워야 모바일 크기 기준을 지킵니다(자동 검사는 변형 전 크기를 잼).
- `text`의 `cols`, `colGap`, `h` — 신문처럼 여러 단으로 나눕니다. 높이를 넘으면 가로 넘침으로 검사에 걸립니다.
- `{ type: 'tone', quad, filter }` — 바탕 그림 일부(예: 기사 사진)에만 색 보정(흑백 등)을 겁니다.
- `{ type: 'smudges', x, y, w, h, lines, opacity }` — 빈 칸을 판독 불가 흐린 인쇄 흔적으로 채웁니다(글자 아님).
- `fragment`의 `transform`, `blend`, `soft` — 바닥에 누운 종이 원근(예: `scaleY(.72)`), 곱하기 합성, 살짝 흐림. 세로로 줄이는 만큼 글자를 키웁니다.
- `clock`의 `face`·`rim`·`ink`(색), `shade`(판 명암), `grain`(미세 노이즈, 숫자는 불투명도), `shadow`(벽 그림자), `soft`(흐림 px) — 합성 시계를 원본 벽시계와 맞춥니다. `--cctv-filter`를 쓰면 시계에도 바탕과 같은 색감 필터가 적용됩니다(E03에서 사용).
- 판독 불가 시계(SPEC `wall_clock_legible: false`, E02): 바늘·눈금을 낮은 대비 색(`dimInk`, 기본 `#a29d94`)으로 그리고 3.5px 흐림 + 유리 반사 하이라이트를 더하며, 원본 벽시계 바늘이 비치지 않게 불투명하게 덮습니다.
- 바탕 그림 가장자리에 이음매 같은 결함이 있으면 원본은 두고 잘라 낸 사본(`work/`)을 바탕으로 씁니다.

## 안전장치
- **원본 보존:** 입력 파일은 읽기만 하고, 합성 전후 해시를 비교합니다.
- **게임 폴더 보호:** `assets/` 안으로는 출력하지 않습니다. 게임 증거 교체는 승인 후 직접 복사합니다.
- **결정 대기:** `status`가 `blocked:*`인 ID(현재 E04d)는 `--sample` 없이 합성하지 않습니다.
- **Git 제외:** `output-preview/`와 `work/`는 `.gitignore`로 제외됩니다. 바탕 그림 작업 파일은 `work/`에 둡니다.

## 자동 검사 항목
- 필수 문자열이 모두 화면에 있는지
- 금지 문구, 날짜·요일 형식, 공식과 다른 등록번호가 없는지 (등록번호 금지 증거는 번호가 아예 없는지)
- 번호 일부(E15)가 공식 번호의 일부이면서 전체는 아닌지
- NVR 표시 시각 + CANON 오차 = 벽시계 시각 (E02 22:05 → 22:12, E03 22:34:13 → 23:01)
- E04a 공유 시각 = E02의 실제 시각 (같은 순간)
- 녹음 시작 + 길이 = CANON의 종료 시각 (E07)
- 출력 형식(WebP), 크기와 비율, 파일 생성
- 한글 글꼴이 실제로 설치되어 쓰였는지 (명조·고딕·고정폭)
- 모바일 표시 폭 340px에서 핵심 문자열 9px 이상, 나머지 7px 이상인지
- 글자가 캔버스나 상자를 넘치지 않는지, 글자끼리 겹치지 않는지(회전 전 배치 좌표 기준)

## 사람이 확인해야 하는 것
자동 검사는 **도구가 합성한 글자**만 확인합니다. 아래 항목은 미리보기 페이지에 체크리스트로 나옵니다.
- 바탕 그림에 AI가 만든 가짜 글자, 숫자, 날짜
- 인물 식별(스프라이트 구별 포인트), 같은 순간 사진끼리의 인물 배치
- 바탕 그림 속 시계 바늘, 또는 판독 불가여야 하는 장면에서 시계가 정말 읽히지 않는지
- 합성 글자가 종이·화면 원근과 어울리는지

## 작업 순서 (증거 1장)
1. SPEC §2에서 해당 ID의 프롬프트로 바탕 그림을 만들어 `work/`에 둡니다.
2. 종이나 화면 위치가 다르면 `layouts.js`의 좌표만 조정합니다.
3. `render <ID> --base work/<파일>`을 실행하고 `output-preview/index.html`을 확인합니다.
4. 승인을 받은 뒤 `assets/evidence/<기존 파일명>`으로 교체하고, `evidence-audit` 절차와 `node tests/logic-assets.test.js`로 확인합니다.
