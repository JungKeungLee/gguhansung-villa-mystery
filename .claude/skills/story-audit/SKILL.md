# story-audit

**기준:** `docs/STORY_CANON.md`가 정답입니다. 이전 분석 결과는 `docs/STORY_AUDIT.md`에 있으며, 이미 정리된 항목(S#, I#, F#, D#)은 **다시 조사하지 않고 ID로 인용**합니다.

## 범위 제한
1. `git status --short`와 `git diff --stat`로 변경된 파일·대사·증거를 먼저 파악합니다. **변경된 부분만** 검토합니다.
2. 소스는 필요한 식별자만 Grep으로 찾아 읽습니다. 예: `const PUZZLES`, `TIME=`, `SLOTS`, `MOTIVES`, 특정 증거 ID, 특정 인물 이름의 대사. 챕터 파일 전체를 통째로 읽지 않습니다.
3. CANON에 없는 정보가 필요할 때만 관련 파일을 추가로 조사합니다.

## 점검 순서
1. **시간:** 변경된 시각을 CANON D장과 비교합니다. NVR 표시 = 실제 − 7분(15:48 이후) 또는 − 26분 47초(22:44:05 이후). 퍼즐 정답(챕터 3·5 시간표, P06)과의 일치를 검산합니다.
2. **인물:** 진술, 위치, 알리바이가 CANON C장과 맞는지 봅니다. 미확인 동선은 채우지 않습니다.
3. **증거 연결:** 퍼즐의 필요 증거가 획득 가능하고, 정답이 사전에 노출되지 않는지 봅니다.
4. **엔딩:** 챕터 5 TRUE/NORMAL/BAD 조건과 근거 증거의 출처를 확인합니다.

## 출력
- 표 하나: `분류([확정 버그]/[설정 모순]/[확인 필요]/[개선 제안]) | 내용 | 근거(파일·함수·ID) | CANON 항목`
- 새 결정이 필요하면 CANON의 D 목록 형식으로 **제안만** 합니다.

## 금지
- 게임 코드, 대사, 정답, 이미지, 테스트를 수정하지 않습니다.
- `docs/STORY_CANON.md`는 사용자가 결정을 승인한 경우에만 고칩니다.
- commit, push, PR, 배포를 하지 않습니다.
