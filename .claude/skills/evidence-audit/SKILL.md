# evidence-audit

**기준:** `docs/EVIDENCE_IMAGE_SPEC.md`(증거별 필수·금지 요소와 정확한 문자열)를 따릅니다. 인물 외형은 `docs/STORY_CANON.md` C장, 결정 변수(`{D1}` 등)는 CANON E장을 봅니다. 이미 검사한 결과는 `docs/STORY_AUDIT.md` 8장에 있으니 다시 분석하지 않습니다.

## 범위 제한
- **요청받은 ID**, 또는 `git status --short assets/`에서 새로 생기거나 바뀐 이미지만 엽니다. 증거 이미지 전체를 매번 보지 않습니다.
- 같은 이미지인지 의심되면 `sha256sum`으로 먼저 비교하고, 그다음 내용을 봅니다.

## 점검 순서 (이미지 1장마다)
1. **연결:** Grep `EVIDENCE_IMAGES`(`chapter3~5.js`)로 ID → 파일 매핑을 확인합니다. 경로 존재와 대소문자는 `node tests/logic-assets.test.js`로 확인합니다.
2. **명세 대조:** SPEC의 해당 ID 항목에 있는 필수 요소, 금지 요소, 시각·날짜, 문자열·번호를 하나씩 대조합니다. 결정되지 않은 `{D#}` 값이 들어간 이미지는 "결정 대기"로 표시합니다.
3. **인물:** CANON C장의 구별 포인트로 식별합니다. 확신이 없으면 **"확인 필요"**로 둡니다. 특히 윤해준·꾸티뉴, 다뮤_·윤타미를 주의합니다.
4. **퍼즐:** SPEC에 적힌 관련 퍼즐의 정답 근거가 이미지에서 성립하는지 봅니다. 정답 직접 노출(실명, "피의자", 강조 표시)은 금지입니다.

## 출력
- `ID | 파일 | 판정(통과/수정 필요/결정 대기) | 어긋난 SPEC 항목 | 근거(이미지에서 읽은 값)`
- 제작 명세 요청이면 SPEC 해당 항목을 요약해 전달하고, 새 정보가 필요하면 CANON D 목록 형식으로 제안합니다.

## 금지
- 이미지 생성·교체·삭제, 코드 매핑 변경을 하지 않습니다.
- 사용자가 승인하지 않은 SPEC·CANON 수정을 하지 않습니다.
- commit, push, 배포를 하지 않습니다.
